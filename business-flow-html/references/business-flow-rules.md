# Business Flow HTML Rules

## 1. 先抽象阶段

复杂阶段型流程先提取 4～8 个阶段；简单流程可用紧凑视图，系统泳道、状态或页面路径按实际语义组织，不强制套阶段卡片。例如：

- 启动
- 准备
- 执行
- 结果处理
- 后续流转
- 收口
- 日切 / 结束

每个阶段必须有清晰业务目的。

## 2. 箭头规则

允许：
- 阶段主线 `→`
- 阶段内顺序 `→`
- 上下判断 `↓`
- 局部 Yes / No 分支

响应式不可破坏流向：
- 宽屏中阶段主线使用高对比度的粗长、宽箭头横向连接；
- 阶段内子流程使用细线、窄箭头横向连接，视觉强度必须低于主流程；
- 中窄屏改为单列时，箭头同步改为向下并保持可见；
- 不得使用 `display:none` 隐藏主线或节点间箭头；
- 相邻阶段卡片之间保留独立的粗长向下箭头，子流程转为单列时使用细向下箭头。

避免：
- 从底部跨越多个区域返回顶部
- 一根线穿过多个阶段
- 多条分支线交叉
- 用箭头表达所有异常细节

## 3. 判断节点

判断节点优先写成：

- 是否满足条件？
- 是否完成？
- 是否命中？
- 是否有效？
- 是否允许继续？

判断后：
- Yes 走主路径
- No 进入局部结束 / 等待 / 异常
- 不要把 No 分支绕回主图远处

## 4. 结束状态

明确区分：
- 正常结束
- 等待
- 异常
- 作废 / 终止

但不要依赖颜色才能理解，文本本身必须完整。

## 5. 折叠规则

阶段型流程必须提供全局控件：
- “全部展开”：展开所有阶段和规则说明
- “全部收起”：收起所有阶段和规则说明

全局控件默认放在主流程概览上方、靠右展示，并标明控制对象为“阶段内容”，避免被理解为仅控制某一阶段或主流程卡片。

全局控件之外，仍保留每个阶段和每段规则说明的局部展开／收起能力。

默认折叠：
- 复杂业务规则
- 异常补充
- 口径说明
- 边界条件

默认展开：
- 主路径
- 关键判断
- 关键结束状态

## 6. 文案规范

节点：
- 标题：短
- 说明：一句话
- 避免整段 PRD

规则展开区：
- 可保留更完整说明
- 仍尽量使用 1～3 条短规则

## 7. 结果导向表达

- 先写用户、业务或下游最终获得的结果，再保留实现该结果所必需的流程节点。
- 页面展示类流程以“进入路径 → 直接展示的结果 → 使用结果”组织主线；不要把“作为展示入口”“系统承载能力”等实现说明作为主结论。
- 当前交付图不出现已废弃的页面、菜单或方案名称。需要说明边界时，仅在折叠规则中使用简短、必要的表述。
- 后台计算、接口和数据沉淀仅在改变流程走向、结果、职责或异常处理时出现；节点描述应落在业务结果，而非技术实现动作。
