# Business Flow HTML

目标：按业务、系统或页面语义，把流程转换为适合评审、汇报和需求文档配套使用的 HTML 视图。

## 流程类型

生成前必须明确一种主视图类型，不在一张图中混用三层语义：

- **业务流程**：表达业务为什么这样运转，突出角色、业务阶段、关键判断和业务结果。
- **系统流程**：表达系统如何支撑业务运转，突出系统边界、触发、数据／状态交接和异常出口，优先泳道、时序或状态视图。
- **页面流程**：表达用户如何通过页面完成操作，突出入口、页面／弹窗／抽屉节点、关键操作、反馈和结果。

## 核心原则

- 复杂阶段型流程先拆成 4～8 个阶段；简单业务流程使用紧凑视图，不为凑阶段而扩写。
- 主路径、关键判断和结束状态常显；规则、异常和补充口径默认折叠。
- 流程箭头在所有支持的视口宽度下必须持续可见；宽屏使用横向箭头，中窄屏改为单列并使用向下箭头，不得在响应式断点直接隐藏连接符。主流程使用粗长、宽箭头连接，子流程使用细线、窄箭头连接，通过箭头层级直接区分主次。
- 所有阶段型流程必须提供“全部展开”和“全部收起”全局控件，同时保留阶段与规则说明的局部折叠控件。
- 节点标题尽量 4～12 个字，不把 PRD 大段规则放入节点。
- 只保留当前主视图类型必需的信息；业务流程不被后台实现步骤淹没，系统流程不复制业务说明，页面流程不复制字段规格。
- 不改变用户含义，不补造规则；发现冲突或缺口时先指出。
- 当前模板以阶段型流程为主。明确需要泳道、状态机或数据流视图时，应按该语义设计，不强行套用阶段卡片。

## 触发边界

- 独立任务中，用户明确要求生成或优化业务、系统或页面流程 HTML 时使用。
- 接受用户直接提供的流程事实，也接受澄清、方案或 PRD 的相关章节；不要求先执行任何上游 Skill。各类图按必要性判断或用户明确要求生成，不因位于正式目录而强制绘图。
- 单独调用完成本次流程即交付；串联只在用户已授权的范围内继续，确认流程不自动授权编写 PRD。
- 字段说明、配置项清单或数据字典不单独触发。

## 运行时最小读取

生成时只读取：
1. 用户提供的流程图 / PRD 相关章节 / 流程描述；
2. `references/business-flow-rules.md`；
3. 新建阶段型流程时，运行 `sh .agents/skills/business-flow-html/scripts/create_flow_workdraft.sh <目标路径>` 复制黄金骨架，不读取完整参考文件；扫描目标 HTML 的结构标记后，只读取和替换正文片段。

修改既有流程只读取受影响片段。只有新增控件、布局或修改黄金参考时，才读取 `references/reference-business-flow-v3.html` 的相关 CSS、HTML 或 JS 片段，仍不默认读取全文。

不要遍历无关文件。

## 输出要求

- 输出可直接浏览器打开的单文件 HTML。
- 默认使用纯 HTML + CSS + JS，不依赖前端框架。
- 业务、系统和页面流程统一放在当前需求目录的 `flows/`，不与页面原型 `prototype/` 混用。
- 共创／方案工作稿：`flows/workdraft/<flow-name>.html`，允许覆盖同名工作稿。
- 用户确认后固化：`flows/最终确认版/<flow-name>.html`；不依赖 PRD 是否已生成。再次确认后替换旧终态，清理工作稿或旧版本前单独确认。
- 由本 Skill 维护 `flows/流程清单.md`，记录流程名称、类型、必要性、来源、工作稿／终态路径及确认状态；目录外单图任务可在交付说明中提供同等信息，不强制建需求档案。
- 独立于正式需求生成时，使用用户指定目录；未指定则先询问保存位置。

所有调用先读取[阶段产物与交接协议](../_shared-requirement-protocol.md)。只写入自己的流程清单、HTML 及已有需求信息中的当前状态；需求层面的必要性判断和方案内容由其责任 Skill 维护。

## 轻量验收

1. 生成前在当前上下文压缩出 Flow Spec，明确 Flow Type，只保留阶段、主路径、判断、出口和会改变流向的规则，无需落盘。
2. 生成后直接对照 Flow Spec，不重读原 PRD；检查阶段、主路径、Yes/No 出口和结束状态。
3. 使用可用的浏览器打开一次，只检查首屏、全部展开／全部收起、阶段展开／收起、规则折叠、流程箭头、明显溢出和控制台错误；至少增加一个中窄视口检查箭头是否切换为纵向且仍可见。
4. 定义不足时先回补并重新确认来源内容；校验通过后请用户确认。确认后固化流程并记录有效路径；涉及 PRD 链接或正文修订时交给 `prd-writing`，不自行修改 PRD。

## 自我进化

现有模板不足以表达当前需求时，允许直接在当前 HTML 中新增控件、布局或样式，不得为套用旧模板而损失业务语义。单次生成不直接修改公共模板。

新表达经用户确认且被明确指定为可复用，或在至少 2 个已确认流程中重复出现时，再单独升级黄金参考。升级时只读新控件所在片段和黄金参考的相关结构，不扫描历史流程全文。可升级的类型例如：
- 并行泳道；
- 多角色协作；
- 状态机；
- 多系统交互；
- 数据流 + 业务流混合。

普通文案差异和一次性业务节点不进入公共模板。
