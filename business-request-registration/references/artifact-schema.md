# 业务诉求登记产物格式

## 诉求登记表

路径：`01_Business_Requests/诉求登记表.md`

登记前使用当日编号前缀和主题关键词定向检索。同一诉求复议或补充时更新原编号，不新增重复记录。

字段：

| 字段 | 说明 |
|---|---|
| 编号 | `REQLOG-YYYYMMDD-序号`；按登记日期查询当日最大序号后递增 |
| 登记日期 | 用户确认处理结论并完成登记的日期 |
| 状态 | 讨论中、待补充、已登记、已转正式需求或已关闭 |
| 国家 | 诉求适用国家；跨国时如实填写 |
| 产品 | 业务产品或产品线 |
| 诉求主题 | 可检索的一句话主题 |
| 诉求文档 | 单诉求标准文档的相对链接 |
| 关联正式需求 | 升级后填写需求编号和相对链接；未升级时留空 |

详细背景、痛点、结论、依据和备注只保留在单诉求文档中。如现有台账仍为旧版宽表，在下次登记或更新时一次性缩减为上述索引字段，不改动单诉求文档。

## 单诉求文件夹

路径：`01_Business_Requests/<诉求编号>-<简短主题>/`

默认创建 `诉求记录.md`。只有确有业务方截图、邮件或其他原始材料时，再创建 `参考资料/` 子目录并保留原文件名。

## 标准诉求文档

文件：`01_Business_Requests/<诉求编号>-<简短主题>/诉求记录.md`

```markdown
# <诉求主题>

## 1. 基本信息

- 诉求编号：<编号>
- 国家：<国家>
- 产品：<产品>
- 来源业务方：<业务方或待补充>
- 诉求提出时间：<时间或待补充>
- 登记时间：<YYYY-MM-DD>
- 状态：<当前状态>
- 关联正式需求：<需求编号和相对链接；没有则写“暂无”>

## 2. 原始诉求

<尽量保留业务方原始表达，不补造事实>

## 3. 背景与痛点

<已确认的背景、问题及业务影响>

## 4. 已确认事实与约束

- <事实或约束>

## 5. 关键判断

<影响处理结论的判断及其依据>

## 6. 处理结论

<用户确认的当前处理结论>

## 7. 结论支撑论点

1. <论点一>
2. <论点二>

## 8. 待确认事项

- <待确认或待补充内容；没有则写“暂无”>

## 9. 结论变更记录

- <日期、原结论、新结论和变化原因；首次登记记录初始结论>
```
