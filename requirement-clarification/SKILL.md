# 正式需求澄清

先读[阶段产物与交接协议](../_shared-requirement-protocol.md)，再按任务读取[建档、澄清与方案确认](../prd-requirement-lifecycle/references/workflow-discovery.md)。

## 输入与职责

- 接受原始需求、已登记诉求或其他材料，不要求先执行诉求登记；尚未进入正式需求的轻量讨论使用 `business-request-registration`。
- 独立调用可在正式需求目录或用户指定位置完成，只输出当前结果；不因确认内容自动开始绘图或 PRD。
- 负责 `01-需求共创记录.md`；用户要求建档时归集相关材料，要求方案确认时整理 `02-方案确认.md`。已有等效确认材料时不补造共创过程。
- 负责需求层面的流程必要性判断与最小事实输入；流程清单及 HTML 由 `business-flow-html` 维护。

## 执行

1. 处理新需求建档时检查收件箱并按相关性读取；仅澄清指定材料时直接读取该材料，不因保存目录扩大输入范围。
2. 按目标、范围、角色、系统边界、核心对象／状态、规则、页面路径的依赖顺序澄清，只询问会改变方案的阻塞问题。
3. 使用 `Dxxx`、`Qxxx` 和范围外事项维护有效结论，不记录逐轮对话或推理。
4. 明确流程图是否必要及原因，允许不生成图，仍需定义必要的流程事实。仅澄清时到达可交接基线即交付；仅在已有串联授权时将必要流程交给 `business-flow-html`。
5. 用户要求方案确认时，读取已有确认输入及必要流程结果；必要图未确认则说明缺口，不固化方案。不需要图时可直接确认文字方案。
6. 按实际完成范围更新索引，未执行阶段如实记录；不编写 PRD、评审或原型。

不把未确认内容当作事实，非阻塞事项明确标记。不读取 `_shared-wiki` 或自行修改公共经验。
