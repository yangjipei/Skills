# PRD 第 6 章编写规则

- **6.1 现状分析**：描述当前流程、系统能力、问题及影响，区分事实与判断。
- **6.2 方案概览**：概括整体方案、核心流程、系统职责和关键数据流转。
- **页面功能**：标题直接写完整菜单路径，不用中括号，例如 `6.3.2 路径：Overdue Cases / Operational Strategies / Strategy Configuration`。每个独立功能包含“功能描述、界面原型、业务规则”。
- **功能描述**：写明目标用户、场景、前置条件、主要操作和处理结果。
- **界面原型**：章节只包含“查看 XXXX 界面原型”链接和按页面实际区域拆分的多张字段说明表，不写界面结构摘要，不为字段说明另设子章节。使用“**查询条件字段说明**”“**列表字段说明**”“**新增／编辑字段说明**”等加粗分组名；复杂配置、详情或监控页面按实际区域命名。同一字段用于不同区域时允许重复出现，并分别定义该区域交互。每张表固定且仅使用 `字段｜类型｜字段说明｜交互规则` 四列，不得增加其他列；类型写控件或展示类型，必填、来源或枚举、默认值、校验、联动、只读和禁用条件按实际需要合并写入交互规则，未知内容标为待确认。字段名称清单或原型画面不能替代字段定义。
- **业务规则**：必须先按实际类别设置编号小标题，再以简洁有序列表描述可判断、可执行、可验证的规则；除非用户明确要求，不使用 `BR-xxx` 编码。类别可包括展示与查询、准入与排除、状态流转、时间与优先级、防重与幂等、权限与异常；APP 端可加离线与重试。
- **无页面功能**：定义输入、输出、系统处理、依赖、权限、异常和验收。
