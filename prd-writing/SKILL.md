# PRD 编写

先读[阶段产物与交接协议](../_shared-requirement-protocol.md)，再读取[PRD 工作稿与终态交付](references/workflow-prd.md)的对应部分及按需写作规则。

## 输入与准入

- 接受已确认方案及流程，或用户提供的目标、范围、功能、规则和流程事实。无论保存位置如何，不要求先执行澄清或生成 `02-方案确认.md`。
- 检查流程图必要性：已有判断时复用，没有时按[流程集成规则](../business-flow-html/references/business-flow-integration.md)判断。仅明确需要的图须确认，不需要时记录原因并用文字定义流程。
- 缺少关键事实时只提出最小问题；需要其他阶段产物时说明具体缺口，不要求补跑无关阶段。

## 执行与交付

1. 默认输出到需求目录的 `03-PRD/`，独立任务可使用用户指定位置，位置不明再询问。首次使用脚本成对创建工作稿；已有工作稿时直接修订，不重复创建。
2. 按标题索引批量读取受影响章节和写作规则，保持主文档第 1～6 章、补充信息第 7～11 章的边界。
3. 不用原型或流程链接替代关键定义。PRD 引用由本 Skill 维护；流程文件的生成、修改和确认交给 `business-flow-html`。
4. 发现输入冲突时暂停受影响内容；仅缺事实时向用户确认，需要改其他产物时按协议交接。
5. 用户确认后成对固化唯一终态。若本次明确包含评审，先完成约定范围内的评审与必要修订，再请求最终确认；独立编写不强制补做评审。
6. 更新当前基线和下游受影响状态，交付后停止；仅在已有串联授权时继续下一阶段。不写入评审、流程、原型或归档产物。

不读取 `_shared-wiki`。
