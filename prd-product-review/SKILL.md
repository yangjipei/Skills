# PRD 产品专家评审

先读[阶段产物与交接协议](../_shared-requirement-protocol.md)，再读取[专家评审规则](references/workflow-review.md)。

## 输入与产物

- 默认位于 PRD 编译 / 定稿之后，但接受任意用户指定 PRD，不要求前序一定由本链路生成。
- 输出 `04-评审记录/产品专家评审.md`；记录文件路径、SHA256、评审范围和复审状态。
- 只读当前评审需要的 PRD 章节；只有发现具体交叉冲突时才增量读取对应需求分析 / Flow / Page Spec，不默认重读完整上游链路。

## 评审边界

重点检查：

- 目标是否是真正业务目标；
- 核心 S 场景是否在 PRD 中形成闭环；
- 流程起点、分支、终点是否完整；
- 对象 / 状态 / 规则是否一致；
- 页面契约是否与已确认 Spec 冲突；
- 异常 / 边界是否足以研发和测试；
- 核心规则是否可验收。

不重写 PRD，不输出技术会审，不为了“更完整”罗列低价值建议。

## 问题路由

- 业务诉求理解、Problem / Goal / Scope、核心业务规则：`requirement-analysis`
- 流程闭环 / 流向：`business-flow-html`
- Page IA / 页面字段 / 交互：`prd-html-prototype`
- 文档表达 / 结构 / 编号：`prd-writing`

评审只记录问题和建议。已有串联授权时可路由，否则交付问题清单。修订后只复审受影响内容；未复审的新基线不继承旧结论。

不读取 `_shared-wiki`。
