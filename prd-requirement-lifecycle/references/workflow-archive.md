# 完成、归档与重开

仅在准备归档或重开已归档需求时读取。

## 1. 完成条件

- 阻塞问题关闭；
- 重要问题已有结论；
- 双方约定的专家评审及必要复审完成；默认范围仅为产品专家评审，其他专家仅在用户明确指定时加入；
- 用户确认最终 PRD；
- 若需要页面原型：已生成、浏览器校验并由用户确认。

## 2. 归档

归档前：

1. 检查 `02_Inbox/`，将仍与该需求相关的材料迁入需求目录的 `参考资料/`，保留原文件名；
2. 确认 `00-需求信息.md` 的“续作索引”能定位用户已确认的当前 PRD、约定评审范围、未决事项及必要的流程或页面原型；
3. 做一次低成本机械检查，不重读 PRD 正文：检查当前 PRD 文件、已迁入的 Inbox 材料和当前产物中被引用的本地相对链接是否存在；
4. 获得用户归档同意后，将包含当前确认需求和相关 Inbox 材料的整个需求目录移至 `03_Requirements/已归档/YYYY-MM-DD/`。

归档是移动当前已确认的需求目录，不额外生成重启文件、当前版索引或历史归档结构；恢复信息直接覆盖更新在 `00-需求信息.md` 的“续作索引”中。已存在的需求文件原样随目录归档；如需删除旧版本或其他文件，将其作为独立操作列出目标和影响，再获得用户明确确认。

## 3. 重开

将原需求目录移回“进行中”，保留编号。首次只读取：

1. `00-需求信息.md` 的“续作索引”，定位当前目标、下一动作、用户已确认的 PRD 和约定评审范围；
2. 对当前 PRD 扫描标题索引，只读本次变更涉及的章节；
3. 续作索引指向且与本次变更直接相关的原型、流程或参考材料。

续作索引缺失或失效时，先用文件名、标题索引和局部章节重建并写回一次，不通读历史版本自行猜测。当前 PRD 位置或评审范围仍无法确定时，再请用户指定；重开不得自动扩大原评审范围。重开不是独立状态。
