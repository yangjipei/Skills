# 完成、归档与重开

仅在准备归档或重开已归档需求时读取。

## 1. 完成条件

- 阻塞问题关闭；
- 重要问题已有结论；
- 双方约定的专家评审及必要复审完成；默认范围仅为产品专家评审，其他专家仅在用户明确指定时加入；
- 用户确认最终 PRD；
- 若需要页面原型：已生成、浏览器校验并由用户确认。

## 2. 归档

归档前：

1. 确认 `00-需求信息.md` 的“续作索引”能定位已确认的当前 PRD、约定评审范围、未决事项及必要的流程或页面原型；
2. 建立最小结果集合：`00-需求信息.md`、当前有效 PRD、被当前 PRD 引用的流程图和原型，以及当前 PRD 未覆盖但续作必需的结果材料；不保留工作稿、历史版本、共创／方案／评审过程或原始输入材料作为追溯依据；
3. 做一次低成本机械检查，不重读 PRD 正文：检查结果集合中的本地相对链接均存在；
4. 若结果缺少续作必需的结论，只按需读取对应过程片段，将结论补入当前 PRD 或 `00-需求信息.md`，再重复第 3 步；不得为保留过程而扩大结果集合；
5. 获得用户归档同意后，将结果集合归档至 `03_Requirements/已归档/YYYY-MM-DD/`；列出拟删除的过程材料、用途和删除影响，获得用户明确确认后再删除。

归档是可直接续作的结果快照，不额外生成重启文件、当前版索引或历史归档结构；恢复信息直接覆盖更新在 `00-需求信息.md` 的“续作索引”中。重开时只按索引读取结果片段，历史过程不作为默认或兜底读取来源。

## 3. 重开

将原需求目录移回“进行中”，保留编号。首次只读取：

1. `00-需求信息.md` 的“续作索引”，定位当前目标、下一动作、用户已确认的 PRD 和约定评审范围；
2. 对当前 PRD 扫描标题索引，只读本次变更涉及的章节；
3. 续作索引指向且与本次变更直接相关的原型、流程或参考材料。

续作索引缺失或失效时，先用文件名、标题索引和局部章节重建并写回一次，不通读历史版本自行猜测。当前 PRD 位置或评审范围仍无法确定时，再请用户指定；重开不得自动扩大原评审范围。重开不是独立状态。
