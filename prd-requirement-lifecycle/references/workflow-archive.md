# 归档与重开

仅在用户要求归档或重开时读取；由 `requirement-archiving` 执行。准入与状态沿用[共享协议](../../_shared-requirement-protocol.md)。

## 1. 核对当前结果集

- 接受正式需求目录或用户指定的等效成果，不要求执行过固定前序流程。
- 确认用户指定的有效基线与本次交付范围；范围内的阻塞问题须有结论，已有确认不可套用于后续修改。
- PRD 及补充信息、必要流程和所需原型按实际范围核对。缺少本次必需成果时说明具体缺口，交责任 Skill 处理；不为了归档补造方案、Spec 或流程图。
- 已约定评审的范围应有评审及必要复审结论；未执行、未覆盖当前基线或不适用时如实记录并告知用户，不假称通过，也不把未约定的评审变成归档前置条件。
- 用户确认当前结果集并明确要求归档即可执行；同一授权不重复确认。归档不代表上线。

## 2. 保留与清理

保留：

1. `00-需求信息.md`，含续作索引、实际阶段状态和未决事项；
2. 当前有效 PRD 与配套补充信息；
3. 当前 PRD 引用或本次独立交付的有效流程、流程清单、页面原型及其 Spec；
4. 最终评审结论及所审基线、问题处理和必要复审结果。若完整结论已保存在需求信息中，可经确认清理重复评审过程；
5. 相关原始参考资料；收件箱中尚有本需求相关材料时保留原名归集到 `参考资料/`；
6. 其他尚未被当前成果吸收、但续作必需的决策与结果。

仅以下材料可列为清理候选：工作稿、历史版本，以及结论已被当前交付物完整吸收的共创、方案、评审过程文件。逐项列明目标、用途、吸收位置与删除影响，获得用户明确确认后再清理；未获准时保留并标为待清理，不能删除唯一依据。

缺少业务结论时，由对应责任 Skill 补齐；归档 Skill 只更新索引及文件组织，不改写 PRD。不要为压缩归档体积删除相关原始资料。

## 3. 移动与校验

1. 更新索引，使其能定位有效成果、最终评审结论及适用基线、未决事项和必要参考资料；未执行阶段如实记录。
2. 检查结果集本地相对链接存在。路径需要修订时交责任 Skill 更新，归档本身不重读或重写 PRD 全文。
3. 按授权整体移动到 `03_Requirements/已归档/YYYY-MM-DD/<原需求目录名>/`，保留编号，不在进行中保留副本。
4. 目标已有同编号目录且内容不同时，以用户明确指定的基线为准；尚未指定时先报告差异，不按日期或状态自行覆盖。
5. 核对移动前后文件完整性、相对链接及唯一有效目录，更新归档日期与状态。

不额外生成重启文件或重复索引；续作入口统一为 `00-需求信息.md`。独立成果缺少该文件时，只补建最小索引，不伪造历史阶段。

## 4. 重开

按用户重开授权将原目录移回进行中，保留编号。先读续作索引，再按本次变更定位 PRD、流程、原型 Spec 或参考材料的相关章节；保留当前终态，在工作稿上修订，再次确认后替换。

索引缺失时先用文件名、标题及局部章节重建。有效基线无法确定时请用户指定，不全文读取历史版本猜测。重开只启动用户要求的变更范围，不重跑整条流水线。
