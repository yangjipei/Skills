# PRD 第 1～5 章编写规则

- **1 文档信息**：记录初始需求内容、需求提出日期、文档日期、需求来源和产品经理。需求上线前的所有变更、反馈与探讨均不罗列于此；需求上线后的正式变更可新增记录，不覆盖既有上线后记录。
- **2 业务背景**：说明业务环境、目标用户、当前流程和核心问题，优先陈述已知事实和数据。
- **3 目标与价值**：定义待解决问题、可衡量结果及对业务、用户、系统的价值。目标值包含指标、基线、目标值、统计周期和口径；基线暂缺时写明获取方式。
- **4 需求范围**：按国家、产品等维度列实际适用组合；功能范围只列能力与边界；非功能范围明确不建设内容；编写 4.4 时读取 `00_Context/role-permission-baseline.md`，仅列本需求涉及的标准角色及其操作事项或负责内容；不展开菜单、页面、按钮、数据范围、数据权限或行级权限。未涉及角色或权限调整时，明确说明不涉及，不输出角色表；涉及自动化职责时可保留“系统”，仅描述后台处理。
- **5 术语定义**：只定义可能歧义的业务术语、状态、指标和系统缩写。
