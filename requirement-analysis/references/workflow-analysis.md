# 需求分析工作流

仅在正式需求分析、场景探索、分析基线更新或向流程阶段交接时读取。

## 1. 最小读取

- 用户只指定一份材料时直接分析该材料，不遍历需求目录。
- 新需求建档或归集收件箱时，先列文件名 / 类型 / 大小 / 时间，再用标题索引、关键词和局部章节判断相关性。
- Markdown 优先使用标题行号索引后一次批量提取目标章节；非 Markdown 先定位页、Sheet 或区域。
- 只有局部内容不足或用户明确要求整体理解时才阅读全文。
- 已有 `01-需求分析.md` 时，先读目标 S/F/D/Q 与受影响章节；小修改不重读全部附件。

## 2. Fact Inventory

```markdown
## 事实清单

| ID | 事实 | 来源 / 备注 |
| --- | --- | --- |
| F001 | ... | ... |
```

事实来源包括：现状、用户明确规则、已有系统能力、已确认范围、状态 / 数据、真实限制。

禁止把推测、UI 设计选择或“通常应该如此”写为事实。

## 3. Problem / Goal

按顺序分析：

```text
业务背景
→ 角色正在完成什么任务
→ 什么条件触发
→ 当前哪里受阻
→ 造成什么影响
→ 希望达到什么结果
```

“新增按钮 / 字段 / Tab / 配置页”只能作为可能方案，不能代替问题定义。

## 4. Scenario Discovery

### 4.1 场景清单

```markdown
## 需求场景清单

| ID | 场景 | 角色 | 触发条件 | 目标 | 分类 | 本期 |
| --- | --- | --- | --- | --- | --- | --- |
| S001 | ... | ... | ... | ... | 核心 | 是 |
```

分类只用：`核心 / 关键分支 / 长尾`。

### 4.2 深入条件

只深入可能改变以下内容的场景：范围、主流程、对象、状态、账务、权限、关键规则、页面结构、留痕、上下游依赖。

### 4.3 六要素

```markdown
### S001 场景名称

- 角色：
- 触发：
- 当前任务：
- 当前问题：
- 期望结果：
- 关键约束：
```

场景的目的不是无限枚举，而是发现真实能力和边界。例如“支持新增联系电话”可能通过不同场景发现号码来源、状态、去重、操作留痕和后续触达规则；这些能力仍需通过本期范围收敛，不能自动全部纳入。

## 5. Scope / Core Rules

```markdown
## 本期范围
### In Scope
### Out of Scope
```

只定义会影响方案的核心对象、状态与规则，优先：

- 资格 / 前置条件
- 状态转换
- 金额 / 账务
- 时间 / 优先级
- 权限
- 去重 / 幂等
- 数据来源
- 操作留痕
- 关键异常

普通字段格式和视觉细节后置到 Page Spec。

## 6. Product Skeleton

```markdown
## 产品能力骨架

### 核心业务对象
- ...

### 核心能力
- ...

### 核心状态
- ...

### 关键规则
- ...

### 页面 / 模块初步映射
| 端型 | 路径 / 模块 | 主要能力 | 建设方式 | 角色 | 覆盖场景 |
| --- | --- | --- | --- | --- | --- |
```

只回答“能力放到哪个产品区域”，不在这里完成详细页面 IA、字段表和视觉规格。

## 7. Decision / Question

```markdown
## 已确认决策
| ID | 决策 | 依据 / 备注 |
| --- | --- | --- |

## 待确认问题
| ID | 问题 | 建议（可选） | 影响 | 阻塞性 |
| --- | --- | --- | --- | --- |
```

每轮优先只问 1～3 个阻塞问题。普通展示细节留到页面阶段，由原型验证而不是逐项文字盘问。

## 8. 流程图规划

```markdown
## 流程图规划

| 流程 | 是否需要 | 原因 | 覆盖场景 | 起点 / 终点 | 最小输入 |
| --- | --- | --- | --- | --- | --- |
| 业务流程 | 是 / 否 | ... | S001,S002 | ... | F001,D001 |
| 系统流程 | 是 / 否 | ... | ... | ... | ... |
```

页面流程此时最多标记“待 Page IA 后判断”；因为页面节点尚未稳定，不应过早绘制页面流。

向 `business-flow-html` 交接时只传目标 Sxxx + 相关 Fxxx / Dxxx + 必要 Qxxx 和起止边界。

## 9. 标准产物

```markdown
# 需求分析

## 1. 原始诉求
## 2. 事实清单
## 3. 业务背景与问题
## 4. 用户与角色
## 5. 需求场景清单
## 6. 核心场景分析
## 7. 业务目标与预期价值
## 8. 本期范围
## 9. 核心对象 / 状态 / 关键规则
## 10. 产品能力骨架
## 11. 页面 / 模块初步映射
## 12. 已确认决策
## 13. 待确认问题
## 14. 流程图规划
```

优先短句、紧凑表格和 ID 引用，不重复抄写同一事实。

## 10. Token 停止条件

达到以下条件停止继续发散：

- 新增场景不再改变本期范围、主流程、核心规则或页面结构；
- 核心场景覆盖主要目标；
- 关键分支覆盖主要业务风险；
- 剩余问题可安全留到流程或 Page Spec 阶段。

需求分析未稳定时禁止主动生成完整 HTML 或完整 PRD。
